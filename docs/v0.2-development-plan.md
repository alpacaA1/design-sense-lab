# Design Sense Lab V0.2 开发规划与技术方案

> 状态：已被 V0.3 文档工作台方向替代。本文保留为历史方案，不代表当前产品结构。

## 1. 目标

V0.2 将当前分类占位入口补全为可工作的参数实验系统。完成后，用户可以在 Document、Web、App 中切换六类设计参数，选择任一参数作为当前实验变量，独立设置 A/B/C，对其他参数使用共享值，并把完整实验上下文保存到 Notebook。

本版本仍是纯前端静态应用，不增加框架、构建工具、后端、数据库、账号或第三方依赖。

## 2. 当前基础

现有版本已经具备：

- Document、Web、App 三种模式与对应预览。
- 基础滑杆和预览实时更新。
- A/B/C 方案选择。
- 场景与判断理由记录。
- Notebook 本地保存和模式筛选。
- 响应式布局、键盘焦点和减少动态支持。

主要缺口是参数体系仍为单层配置，分类按钮只切换样式并显示占位提示；当前变量由模式固定，用户不能切换比较目标，也不能独立设置 A/B/C。

## 3. 采用方案

采用“配置驱动的参数实验引擎”。每个模式只定义参数、范围、控件类型和预览映射；分类切换、共享值、A/B/C 值、状态保持、重置和保存由统一引擎处理。

不采用按页面和分类分别硬编码表单的方案。硬编码短期较快，但会让三种模式产生重复状态逻辑，新增参数需要修改多个渲染分支，难以保证单变量规则持续成立。

## 4. 信息架构与交互

左侧参数区改为单一连续结构：

```text
参数分类
  ↓
当前展开分类
  ↓
分类内参数列表
  ├── 当前实验参数：显示 A/B/C 独立值
  └── 固定参数：显示一个共享值
  ↓
实验状态说明
```

交互规则：

1. 同时只展开一个参数分类。
2. 点击参数名称，将其设为当前实验变量。
3. 当前参数显示 A/B/C 三个值；数值、枚举、颜色和开关使用各自适合的控件。
4. 非当前参数只显示共享值，同时作用于三个版本。
5. 切换当前参数时，旧参数的 B 值成为新的共享值，避免三个版本保留隐形差异。
6. Density 是明确标注的组合实验，可同时改变多个参数；状态栏列出实际变化项。
7. 切换模式和分类不丢失参数；重置只影响当前模式。

## 5. 参数定义模型

每个参数定义包含以下字段：

| 字段 | 用途 |
|---|---|
| 标识 | 模式内稳定且唯一，用于状态和存储 |
| 分类 | Typography、Spacing、Layout、Surface、Color 或 Density |
| 名称与说明 | 告诉用户它主要影响什么 |
| 控件类型 | 数值、枚举、颜色、开关或组合预设 |
| 默认值 | 当前模式的共享基准 |
| 合法范围 | 最小值、最大值、步长或可选项 |
| 默认对比值 | 首次激活时的 A/B/C 合理梯度 |
| 作用目标 | 预览中的具体 CSS 变量或结构行为 |
| 实验类型 | 单变量或组合变量 |

参数定义只描述能力，不直接操作 DOM。控件渲染器负责展示，预览渲染器负责消费解析后的三个版本状态。

## 6. 前端模块规划

保持原生 JavaScript，将当前单文件职责拆分为：

| 文件 | 职责 |
|---|---|
| `app.js` | 应用启动、模式导航和模块协调 |
| `config.js` | 三种模式、六类参数、默认值和合法范围 |
| `state.js` | 当前模式、分类、参数、共享值、A/B/C 和本地持久化 |
| `controls.js` | 分类、参数列表及不同控件类型的渲染与事件 |
| `renderers.js` | Document、Web、App 三种预览渲染器 |
| `notebook.js` | 判断保存、旧数据兼容、筛选和详情展示 |
| `index.html` | 稳定页面骨架与可访问语义 |
| `styles.css` | 设计令牌、参数面板、预览与响应式样式 |

依赖方向保持单向：

```text
config ──→ state ──→ controls
              ├────→ renderers
              └────→ notebook
                        ↑
                       app
```

`controls` 和 `renderers` 不互相调用，只通过状态更新事件协调，避免循环依赖。

## 7. 状态与本地存储

每个模式独立保存：

- 当前展开分类。
- 当前实验参数。
- 所有参数的共享值。
- 当前实验参数的 A/B/C 值。
- 用户选择的方案、理由和场景。

Notebook 新记录增加：模式、分类、当前参数、实验类型、A/B/C 值、共享参数快照和选择结果。现有 V0.1 记录缺少这些字段时，继续按旧版简略卡片显示，不清除、不强制迁移。

本地存储异常时回退到默认状态，页面仍可完成实验；只在保存失败时明确提示“当前判断未保存”。

## 8. 分阶段开发

### 阶段 1：状态模型与配置迁移

- 建立统一参数定义格式。
- 将现有 Document、Web、App 参数迁入六类结构。
- 建立每种模式独立的当前分类、当前参数和参数值状态。
- 保留现有默认视觉结果，防止迁移后预览突变。

交付标准：在控制台切换任意模式和参数时，可以得到完整、合法的三个版本状态。

### 阶段 2：参数面板与控件类型

- 实现单分类展开与参数激活。
- 实现共享值与 A/B/C 独立值界面。
- 实现数值、枚举、颜色、开关和组合预设五类控件。
- 补齐 hover、focus、disabled、错误和边界状态。

交付标准：所有参数都能通过鼠标和键盘操作，当前变量与固定变量不会混淆。

### 阶段 3：三种预览映射

- Document 增加列表、引用块和信息表，接入六类参数。
- Web 增加内容区和卡片模块，接入六类参数。
- App 扩充辅助文字、状态和列表分组，接入六类参数。
- Density 使用三个明确组合预设，并列出变化参数。

交付标准：每个可调参数都能在预览中产生肉眼可见且符合媒介语义的变化。

### 阶段 4：Notebook 完整快照

- 保存完整实验上下文。
- 增加参数分类筛选。
- 为新记录展示 A/B/C 和共享参数摘要。
- 兼容现有 V0.1 数据。

交付标准：重新打开页面后，旧记录和新记录都能正确显示，新记录可以解释结论的产生条件。

### 阶段 5：质量验证与收敛

- 验证 Document、Web、App 各六个分类。
- 验证所有参数的默认值、边界和重置。
- 验证 1440、1280、1024、768、390px 五个宽度。
- 验证键盘顺序、Enter、Space、方向键、Focus 和对比度。
- 检查浏览器控制台和本地存储异常。
- 更新 `DESIGN.md` 与 README。

交付标准：核心路径无错误，设计规则扫描无阻塞项，实际浏览器完成一轮跨模式保存与复盘。

## 9. 排期建议

按单人连续开发估算：

| 阶段 | 预计投入 |
|---|---:|
| 状态模型与配置迁移 | 1～1.5 天 |
| 参数面板与控件类型 | 1～1.5 天 |
| 三种预览映射 | 1.5～2 天 |
| Notebook 完整快照 | 0.5～1 天 |
| 浏览器验证与收敛 | 1 天 |
| 合计 | 5～7 天 |

如果只追求功能跑通，可以压缩到 3～4 天；如果保持当前视觉完成度、响应式和无障碍质量，建议按 5～7 天规划。

## 11. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 参数数量过多 | 左侧面板难以理解 | 单分类展开、当前变量高亮、非当前参数折叠为共享值 |
| 参数变化不可见 | 工具退化为数字播放器 | 为各分类补充可观察内容，参数没有视觉载体时不得上线 |
| Density 破坏单变量原则 | 用户无法解释差异来源 | 明确标记组合实验，并列出所有变化参数 |
| 三种模式状态互相污染 | 切换后出现意外参数 | 每个模式保存独立状态，统一经过状态解析器输出 |
| Notebook 数据结构变化 | 旧记录丢失或报错 | 新字段全部可选，使用向后兼容读取，不覆盖旧数据 |
| 单文件继续膨胀 | 修改一个参数引发多处回归 | 按配置、状态、控件、预览和记录拆分，禁止循环依赖 |
